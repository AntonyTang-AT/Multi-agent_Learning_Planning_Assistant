# 3 号 · 多智能体系统职责说明书

> 关联：[形式化整体方案](../学习计划多智能体系统·形式化整体方案.md) · [技术路线](../技术路线与方案.md)  
> 代码目录：`agent/`

---

## 1. 定位

项目 **唯一智能内核**。计划、检索策略、出题、计算检验、记忆侧推理、评估质疑、元认知/主动干预、黑板智能条目等 **全部在本服务内完成**。  
对 2 号只暴露 **稳定 I/O 接口**；不负责前端样式，不替代 2 号做用户永久存储规范（结果由 2 号落库）。

---

## 2. 做什么 / 不做什么

| 做 | 不做 |
|---|---|
| 主 Agent 路由与各 Worker | 前端组件、CSS |
| 规则审计、SymPy/工具校验 | 用户表、文件上传业务 |
| 结构化质疑、弃答/降级 | 「偷偷改用户计划」不暴露 |
| 共享黑板（进程内/返回条目） | 绕过 I/O 让前端直连本服务（答辩可临时，架构上不鼓励） |
| DeepSeek 等 LLM 调用与 Key 管理 | 资料版权整理（用 4 号数据） |

---

## 3. 内部结构（对齐形式化方案）

```text
invoke 入口
  └─ Orchestrator（主 Agent）
        ├─ Planner      计划草案（含负荷/动机信号）
        ├─ Retriever    检索策略（可先函数）
        ├─ Generator    出题
        ├─ Verifier     计算检验（质量门禁）
        ├─ Memory       轨迹摘要/掌握度推断（轻量）
        └─ Evaluator    质疑 / 元认知 / 干预触发
  共享黑板（conflict|challenge|intervention|...）
```

编排（已锁定）：**intent 路由 + Worker 模块** 为主；**不强制 CrewAI**（有余力可包一层，I/O 不变）。  
状态机在答辩材料中按 LangGraph 式流程图表达。  
逐日任务见 [`docs/五人详细任务计划.md`](../五人详细任务计划.md) §3。

---

## 4. 对外 I/O

**唯一主入口**：`POST /agent/v1/invoke`

输入关注：`scenario`（`final_review`|`catch_up`）、`intent`、`input`、`resource_refs`、`constraints`、`trace_snapshot`。  
输出关注：`status`、`output`、`blackboard_entries`、`user_options`、`evidence_refs`、`requires_approval`。

完整 schema 见 [技术路线 · Agent I/O](../技术路线与方案.md#agent-io)。

## 5. 场景侧重点

| 场景 | 能力重点 |
|---|---|
| 期末复习 | 考点覆盖、时间预算审计、冲突选项、组题 |
| 跟课补漏 | 先修检查、低门槛任务、负荷拆分、概念回顾 |

---

## 6. 实现优先级

| 级 | 能力 |
|---|---|
| P0 | 路由 + 计划草案 + **审计冲突** + `user_options` |
| P0 | 出题 + **检验** + 失败弃答/降级 |
| P0 | 黑板条目随响应返回 |
| P0 | 错因 → 推荐/计划差异（规则即可） |
| P1 | 结构化质疑、负荷/动机信号、元认知卡片、主动干预（时间跳跃） |
| P2 | 搜索独立 Agent、编排框架完整化 |
