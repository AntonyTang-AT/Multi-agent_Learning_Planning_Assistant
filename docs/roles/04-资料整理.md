# 4 号 · 资料搜集与整理职责说明书

> 关联：[五人分工总览](../五人分工与细化落地说明.md) · [项目文件结构](../项目文件结构.md)  
> 数据目录：`data/`

---

## 1. 定位

围绕 **高数 + 大物**，尽量 **宽覆盖** 搜集课件、教材要点、习题、考试真题，整理成 **软件可导入、可按场景筛选** 的结构化数据包。  
服务两大产品场景：**期末复习**、**跟课补漏**。以标注与结构化为主，不写业务后端，不调 LLM 充当生产逻辑。

---

## 2. 做什么 / 不做什么

| 做 | 不做 |
|---|---|
| 大纲（章/节）与知识点 ID | FastAPI / 前端页面 |
| 题目与资料 JSON 规范化 | 盗版全文入库 |
| 场景标签、期末热点、周次对齐 | 伪造「真实用户日志」却不标注 |
| schema 校验脚本 | Agent 提示词 |
| 给 3 号的校验题 / 缺假设样例 / 错因表 | |

---

## 3. 覆盖策略（宽骨架 + 场景够用）

**高等数学**：按本校大纲列全章级（极限、导数、积分、微分方程、级数等）→ 每章要点元数据 + 一定量例题习题；期末向题目打 `exam_hot`。  

**大学物理**：力学 / 热学 / 电磁 / 振动波动 / 光学等（按开课范围）同样建章级入口 + 题与要点。  

深度策略：大纲必须宽；题量可在演示相关章加密，但叙事上是「课程级复习/跟课助手」。

---

## 4. 目录与文件

```text
data/
  README.md
  schemas/                  # JSON Schema（可选）
  taxonomy/
    math_outline.json
    physics_outline.json
  materials/
  questions/
  exams/
  catch_up/                 # 按周次/课次聚合（可选）
  final_review/             # 按考点聚合（可选）
  synthetic/                # 机制验证，必须标注
  scripts/validate_schema.py
```

字段要求见总览与技术路线；至少含：`knowledge_ids`、`scenario_tags`、`difficulty`、`error_tags`、`assumptions`、`verify_hint`、`source`、`license_note`。

---

## 5. 「整理效果」验收

1. 高数、大物均有 **章级可浏览大纲**  
2. 能筛 `final_review` / `catch_up`  
3. `validate_schema.py` 通过；2 号可导入  
4. 若干带 `verify_hint` 的题；2–3 道缺假设样例；错因标签多样  
5. README 写清版权与使用范围  

建议量级（可调）：大纲齐全前提下，高数题 ≥30、大物题 ≥15 为演示舒适区；先 10+5 跑通链路再扩充。
