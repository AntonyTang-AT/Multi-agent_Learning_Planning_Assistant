# 2 号 · 后端职责说明书

> 关联：[五人分工总览](../五人分工与细化落地说明.md) · [项目文件结构](../项目文件结构.md) · [技术路线](../技术路线与方案.md)  
> 代码目录：`backend/`

---

## 1. 定位

**传统 Web 后端**：会话、资料/题目/计划/作答/黑板的持久化与查询；需要智能时对 3 号做 **HTTP 输入输出转发**，并把结果落库后交给前端。  
**不含任何 AI 业务逻辑**（不写提示词、不编排 Agent、不做校验/出题/计划生成）。

---

## 2. 做什么 / 不做什么

| 做 | 不做 |
|---|---|
| 用户/会话（可简化） | 提示词、CrewAI、SymPy |
| 资料包导入与按章/标签查询 | 解读 Agent 内部状态机 |
| 计划、作答、黑板 CRUD | 「如果 conflict 就自动改计划」 |
| `agent_gateway` 透传 invoke | 持有并消费业务提示词（Key 建议只在 3 号） |
| CORS、健康检查、部署说明 | 前端页面 |

---

## 3. 模块划分

| 模块 | 职责 |
|---|---|
| `api/session` | 访客或简易登录，发 `user_id` |
| `api/materials` | 导入/查询 4 号数据 |
| `api/questions` | 题目筛选 |
| `api/plans` | 计划读写 |
| `api/attempts` | 作答保存 |
| `api/blackboard` | 黑板读写与用户 resolve |
| `api/ai` | 组装请求 → 调 3 号 → 存快照 → 返回 |
| `api/demo` | 演示灌数、时间跳跃标记 |
| `db` | SQLite 模型与迁移（可简易） |
| `services/agent_client` | 唯一对外 AI 客户端 |

---

## 4. 技术约定（已锁定）

- **FastAPI + SQLAlchemy 2 + SQLite + Pydantic v2 + httpx + uvicorn** · Python 3.11+  
- 配置：`AGENT_BASE_URL`；CORS 放行前端；**不放 LLM Key**  
- 统一错误体：`{ "code", "message", "detail?" }`  
- OpenAPI + `docs/api.md`  
- 逐日任务见 [`docs/五人详细任务计划.md`](../五人详细任务计划.md) §2。

---

## 5. 与 3 号契约

只认：`POST {AGENT_BASE_URL}/agent/v1/invoke`  

- 超时、连接失败 → `agent_unavailable`，前端仍可读已落库数据  
- **禁止**在网关内写智能分支；`user_options` 原样下发，用户裁决后再决定是否二次 invoke  

详细字段见 [技术路线](../技术路线与方案.md) 与 3 号文档。

---

## 6. 12 号验收

- [ ] **无 3 号**：资料浏览、计划 CRUD、做题存记录完整可用  
- [ ] **有 3 号**：gateway 通，响应写入 DB 可查  
- [ ] 能导入 `data/` 宽覆盖包  
- [ ] `GET /api/health` 返回 `agent: up|down`
