# 演示脚本（草稿）

> 控场：5 号 · 操作：1 号 · 数据/服务：2/3/4  
> 限时约 90–100 秒演示段（含在 3 分钟路演内）

## 开场切入（口播）

「我们选期末复习和跟课补漏两个真实场景……系统不只生成，还会审计、校验，冲突交给用户。」

## 动作 1：审计冲突（必演）

1. 场景选「期末复习」，每日时长设很紧（如 45 分钟）。  
2. 触发生成计划（demo 可 `force_conflict`）。  
3. 展示黑板 conflict + 三个选项；点「降低深度」。  
4. 展示重排后的计划。

## 动作 2：校验弃答（必演）

1. 进入练习，打开会失败的校验演示题 / `force_verify_fail`。  
2. 展示「不通过 → 弃答/提示」，黑板或状态区留痕。  
3. 强调：不强行给不可靠答案。

## 动作 3：错因驱动（必演）

1. 同一知识点切换错因标签。  
2. 展示推荐/计划插入差异（回顾块 vs 基础题等）。

## 可选

- 结构化质疑（缺假设题）  
- 时间跳跃 → 干预卡片  

## Agent 侧一键复现（3 号）

在合入 A5 后，可不启前端先验证三必演：

```bash
cd agent
python -m app.demos.run_three_must
python -m app.demos.run_three_must --with-enhancements
```

固定用例见 `agent/examples/`（`create_plan_final_review` / `verify_answer_force_fail` / 错因对比；增强：`challenge_missing_assumption` 等）。

## 收束口播

「协作过程在黑板可见，最终裁决权在用户。」
