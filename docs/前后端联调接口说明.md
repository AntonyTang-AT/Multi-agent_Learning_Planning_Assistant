## 1. 一句话架构

```text
前端 (5173)  --业务 API-->  后端 (8000)  --透传-->  Agent (8001)
                              │
                              └── CRUD / 落库 / health.agent
```

- **前端不要直连 Agent**（答辩临时调试除外）。  
- **后端不要解析/改写智能语义**（冲突消解、弃答文案等由 Agent 给出）。  
- Agent 唯一智能入口：`POST /agent/v1/invoke`。

## 3. 后端（2 号）需要对齐的接口

### 3.1 健康检查（探测 Agent）

- Agent：`GET http://localhost:8001/health`  
  → `{ "status": "up", "version": "0.1.0" }`
- 后端 `GET /api/health` 应包含：`agent: "up" | "down"`  
  Agent 宕机时 **CRUD 仍可用**，不要整站 500。

### 3.2 AI 网关（B4 核心）

```http
POST /api/ai/{intent}
Content-Type: application/json
```

**推荐实现**：

1. 校验 `intent` 白名单（见 `agent-api.md`）。  
2. 组装/透传 body → `POST {AGENT_BASE_URL}/agent/v1/invoke`。  
3. 超时与连接失败 → 业务错误码，例如：  
   `{ "code": "agent_unavailable", "message": "智能服务暂不可用" }`（HTTP 503 建议）。  
4. **禁止**在网关写「如果 conflict 就本地改计划」等智能分支。  
5. 成功响应：原样返回 Agent JSON（B5 可先落库再返回）。

环境变量：仅 `AGENT_BASE_URL=http://localhost:8001`（LLM Key **不要**放后端）。

### 3.3 落库建议（B5）

从 Agent 响应中可落库的字段：

- `output.plan` → plans 草稿/快照  
- `blackboard_entries[]` → blackboard  
- 全量响应 → `AiCallLog`（可选）  
- 用户选 `user_options` 后 → 再调 `intent=arbitrate` 或写 resolve

### 3.4 联调命令（后端）

```bash
# Agent 需先启动
cd agent && uvicorn app.main:app --port 8001

curl -s http://localhost:8001/health
curl -s -X POST http://localhost:8001/agent/v1/invoke \
  -H "Content-Type: application/json" \
  -d @agent/examples/create_plan_final_review.json
# 注意：examples 文件含 request/response_example 包装时，请只 POST 其中的 request 对象
```

更稳：用 `python -m app.demos.run_three_must` 或 OpenAPI `http://localhost:8001/docs`。

## 4. 前端（1 号）需要对齐的接口

前端只打 **后端**；智能结果来自 `POST /api/ai/{intent}` 的响应（形状 = Agent 响应）。

### 4.1 必须能渲染的通用字段

| 字段 | UI 含义 |
|---|---|
| `status` | 决定页面态：`ok` / `conflict` / `abstain` / `need_user` / … |
| `message` | 顶部提示文案 |
| `output` | 业务载荷（计划、题目、卡片…） |
| `blackboard_entries[]` | 黑板列表（`type`: conflict/challenge/intervention） |
| `user_options[]` | 选项卡（`id` + `label`） |
| `requires_approval` | 是否需用户确认后再持久化 |

### 4.2 三必演对应（对齐 G3）

| 演示 | 调 intent | 期望 status | 关键 UI |
|---|---|---|---|
| 审计冲突 | `create_plan` + `demo.force_conflict=true` | `conflict` | 选项三选一 + 黑板 conflict |
| 用户裁决 | `arbitrate`（带 `option_id` + `plan`） | `ok`（通常） | 更新计划列表 |
| 校验弃答 | `verify_answer` 或 `generate_question` + `force_verify_fail` | `abstain` | 弃答/提示，**不展示假正确答案** |
| 错因差异 | `create_plan` + `input.error_tag` | `ok` | 对比插入的补救任务 + challenge/intervention |

Mock 阶段可直接把 `agent/examples/*.json` 改编进 `frontend/src/mocks`（F2）。

### 4.3 类型建议

以 `docs/agent-api.md` + examples 生成 `frontend/src/types/api.ts`；  
不要自己发明与合同冲突的字段名。

## 5. 已实现 intent 速查（Agent 侧）

| intent | 实现 | 给前端的关键信号 |
|---|---|---|
| `echo` | ✅ 调试 | 勿用于正式产品路径 |
| `create_plan` | ✅ | `output.plan`；冲突时 `user_options` |
| `arbitrate` | ✅ | 重排后的 `output.plan` |
| `generate_question` | ✅ | `output.question` 或 `abstain` |
| `verify_answer` | ✅ | `output.verdict` + `audit_trail`；失败 `abstain` |
| `challenge` | ✅ | `output.card` + 黑板 challenge |
| `metacognitive_feedback` | ✅ | `output.card` |
| `proactive_intervention` | ✅ | `output.card` + 黑板 intervention |
