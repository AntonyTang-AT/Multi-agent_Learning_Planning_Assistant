# 技术路线与方案

> 对齐：[形式化整体方案](./学习计划多智能体系统·形式化整体方案.md) · [项目文件结构](./项目文件结构.md) · [分工总览](./五人分工与细化落地说明.md)  
> 场景：**期末复习** / **跟课补漏** · 学科：高数 + 大物  

---

## 1. 目标与架构原则

**产品目标**：用户选场景、说约束 → 得到可审计的学习计划与可校验的练习；冲突与不可靠答案显式暴露，用户裁决；学习记录落在服务器上。

**工程原则**：

1. **壳核分离**：`frontend` + `backend` = 传统学习 Web；`agent` = 唯一 AI。  
2. **智能不进后端业务代码**：backend 只转发 I/O 并落库。  
3. **规则优先于模型**：审计、校验、质疑触发条件用确定性规则；LLM 负责生成与措辞。  
4. **演示可复现**：固定 `examples/` 与 demo 开关，避免现场抽卡失败。

```text
浏览器
  │ HTTP
  ▼
backend :8000          ← 会话、CRUD、导入 data、落库
  │ HTTP invoke
  ▼
agent :8001            ← 多智能体 + 规则 + LLM + SymPy
```

## 2. 技术栈选型（已锁定）

> 原则：**最契合壳核分离 + 最好上手、最少选型争论**。下列为最终决定，不再二选一。

| 层级 | 锁定选型 | 理由 |
|---|---|---|
| 前端 | **React 18 + Vite + TypeScript** | 组件化清晰；AI 辅助写代码资料多；与类型化 API 契合 |
| 前端 UI | **Ant Design 5** | Table/Form/Modal/Card 开箱即用，计划/黑板/选项卡最快 |
| 前端路由/请求/状态 | **React Router 6 + Axios + Zustand** | 学习成本低，够用 |
| 后端 | **Python 3.11+ · FastAPI · Pydantic v2 · SQLAlchemy 2 · SQLite · httpx · uvicorn** | 与 Agent 同语言；OpenAPI 自动生成；单文件库零部署负担 |
| Agent 服务 | **FastAPI + intent 路由 + Worker 纯函数/模块** | **不强制 CrewAI**：先保证稳定 I/O 与规则；有余力再包 CrewAI，不改接口 |
| LLM | **DeepSeek API**（OpenAI 兼容客户端，仅 agent 内） | 中文与性价比；Key 只在 `agent/.env` |
| 校验 | **SymPy** + 少量规则表 | 门禁可演示、不依赖模型算对 |
| 资料 | **UTF-8 JSON + `validate_schema.py`** | 4 号无后端也能交付 |
| 包管理 | 前端 `npm`；Python **`venv + requirements.txt`** | 全组零学习成本 |
| 演示运行 | **本机三进程**（5173 / 8000 / 8001） | 12 号不做 Docker |

**明确不做（MVP）**：Vue/Streamlit 双轨、CrewAI 硬依赖、LangGraph 硬依赖、向量库、微服务、Docker 必选、原生 App、教务系统对接。

**状态机/架构图**：答辩材料用 LangGraph 式流程图表达；代码层用 intent → pipeline 即可。

## 3. 端到端主路径

### 3.1 期末复习 · 生成计划

1. 前端提交：`scenario=final_review`，考试日、每日分钟、科目、目标（过线/高分）。  
2. 后端校验必填 → `POST /api/ai/create_plan` → gateway 调 agent。  
3. Agent：计划草案 → **审计**（时间/依赖/完成标准）→  
   - 通过：`status=ok`，返回 plan；  
   - 冲突：`status=conflict` + `user_options` + 黑板 conflict 条目。  
4. 后端把 `output`/`blackboard_entries` 写入 DB，原样返回前端。  
5. 用户选「延时间/降深度/调目标」→ 后端存裁决 → 可选二次 `arbitrate` / `create_plan`。

### 3.2 跟课补漏 · 生成计划

同流；`scenario=catch_up`，必填当前章节/周次；Agent 侧重先修与低负荷启动任务。

### 3.3 出题与作答

1. 前端请求下一题（可先纯 DB 按标签取题；或 `generate_question` 智能出题）。  
2. 若智能出题：Agent 出题 → Verifier → 失败则 `abstain`/`doubt`，不把错答当正解。  
3. 用户作答 → 后端 `attempts` 落库；需要对答案时再 invoke `verify_answer` 或本地对标准答案。

### 3.4 错因驱动（演示）

切换/提交 `error_tag` → invoke 或后端取 Agent 预置策略表 → 计划插入不同复习块；前端对比展示。

## 4. Agent I/O {#agent-io}

### 4.1 请求

```json
{
  "request_id": "uuid",
  "task_id": "uuid",
  "scenario": "final_review",
  "intent": "create_plan",
  "user_profile": {
    "user_id": "u_001",
    "constraints": {
      "hard": ["daily_minutes<=120", "exam_date=2026-01-10"],
      "soft": ["prefer_morning"]
    }
  },
  "input": {},
  "resource_refs": [
    { "type": "knowledge", "id": "math.limit", "label": "极限" }
  ],
  "resource_payload": {
    "knowledge_summaries": [],
    "sample_questions": []
  },
  "trace_snapshot": {
    "recent_attempts": [],
    "load_signals": {},
    "motivation_signals": {}
  },
  "demo": {
    "force_conflict": false,
    "force_verify_fail": false,
    "time_jump_days": 0
  }
}
```

**intent 枚举（MVP）**：  
`create_plan` | `arbitrate` | `generate_question` | `verify_answer` | `record_trace` | `challenge` | `metacognitive_feedback` | `proactive_intervention`

### 4.2 响应

```json
{
  "request_id": "uuid",
  "task_id": "uuid",
  "status": "ok",
  "message": "人可读摘要",
  "output": {},
  "blackboard_entries": [
    {
      "entry_id": "bb_001",
      "type": "conflict",
      "summary": "第3天超出每日预算",
      "severity": "high",
      "evidence_refs": [],
      "status": "open"
    }
  ],
  "user_options": [
    { "id": "extend_time", "label": "延长每日学习时间" },
    { "id": "reduce_depth", "label": "降低复习深度" },
    { "id": "adjust_goal", "label": "调整目标" }
  ],
  "evidence_refs": [],
  "requires_approval": true,
  "meta": { "agent_version": "0.1.0", "latency_ms": 0 }
}
```

**status**：`ok` | `conflict` | `doubt` | `failed` | `abstain` | `need_user`

### 4.3 output 形态（按 intent）

| intent | output 关键字段 |
|---|---|
| `create_plan` | `plan.tasks[]`：动作、对象、时长、完成标准、负荷档位、knowledge_ids |
| `generate_question` | `question`：题干、答案、assumptions、knowledge_ids、error_tags |
| `verify_answer` | `verdict`：passed/doubt/failed；`diff`；`audit_trail` |
| `metacognitive_feedback` / `proactive_intervention` | `card`：问题文案 + options |

## 6. Agent 内部技术路线

### 6.1 编排

- **阶段 A**：`intent` → Python 路由表调用对应 pipeline 函数（最快可用）。  
- **阶段 B**：CrewAI Crew/Task 包装 Planner/Generator 等。  
- **阶段 C（可选）**：外层状态用 LangGraph 显式化（答辩 PPT 可先画图不强制代码）。

### 6.2 计划审计（规则引擎，非 LLM）

检查项：总时长 ≤ 预算；单日连续高负荷次数；任务缺 `completion_criteria`；`catch_up` 时先修未覆盖；空 knowledge 绑定。  
失败 → `conflict` + 选项，**不静默改写**。

### 6.3 计算检验

- 数值/符号：SymPy 化简比较。  
- 演示：`demo.force_verify_fail=true` 走弃答文案。  
- 失败策略：重试一次 → 提示模式 → `abstain` + audit_trail。

### 6.4 评估质疑

规则触发：答案依赖未声明假设、多解未说明、标签与知识点不一致等 → `challenge` 黑板条目；Evaluator **不直接生成完整替代方案**（与形式化方案一致）。

### 6.5 负荷 / 动机信号

由 backend 在 `trace_snapshot` 中带滚动统计（中断率、超时比、跳过次数）；无数据时用中性默认。Planner 读信号调任务配比。

- `api/client.ts` 统一错误处理；`mocks/` 与真接口开关。  
- 组件：`UserOptionsCard`、`BlackboardList`、`PlanTimeline`、`QuestionPanel`、`ScenarioWizard`。  
- 演示模式：URL `?demo=1` 显示 DemoBar。

## 8. 资料与推荐技术路线

- **冷启动**：知识点先修图 + 标签过滤（可解释）。  
- **错因演示**：规则表 `error_tag → 策略`（插回顾 / 降难度 / 延迟提取）。  
- **协同过滤**：有余力用合成矩阵跑余弦/Jaccard，标注 synthetic。  
- 宽大纲 JSON 为唯一知识权威；题目挂 `knowledge_ids`。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| Agent 不稳 | 固定 demo 用例；backend 可回放上次成功快照 |
| 接口来回改 | I/O 变更必须改 `agent-api.md` 并通知 1/2 |
| 资料过宽做不完 | 大纲先全；题量按场景标签优先填 |
| 现场无网 | 预录屏 + 本地 Key + 规则桩响应 |
| 职责再次糊掉 | Code review 拒绝 backend 内业务提示词 |
